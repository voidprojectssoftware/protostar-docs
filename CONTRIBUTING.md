# Contributing to Protostar docs

There are two kinds of docs, and they live in two different places.

## 1. Product docs (the common case)

Docs for a specific component — the CLI, and anything that comes later — live in
**that component's own repo**, under its `docs/` folder, next to the code. You
edit them there and review them in that repo's normal PR flow. They appear on the
unified site automatically the next time the site builds.

**You do not need to touch this repo to write product docs.**

Conventions for a product `docs/` folder:

- Markdown or MDX files. The sidebar is **autogenerated** from the folder
  structure, so organize files into folders to create sidebar groups.
- Use frontmatter to control ordering and titles:
  ```md
  ---
  sidebar_position: 2
  title: Installation
  ---
  ```
- The first page (lowest `sidebar_position`) is what the navbar tab links to.
  Give it `slug: /` so it sits at the section root (e.g. `/cli`).
- Optional `_category_.json` files customize sidebar group labels and order.
- Links between docs in the same product use relative paths
  (`./installation.md`). Links to another product use site-absolute paths
  (`/cli/installation`).
- Assets (images) referenced by a doc should live in that product's `docs/`
  folder so they are lifted along with the Markdown.

The "edit this page" link on the site points back to the source file in the
product repo, so readers always land in the right place to propose a fix.

## 2. Hub docs (project-wide)

Docs that do not belong to any single component — the project overview, shared
concepts — live in **this repo**, under `docs-hub/`. Same Markdown conventions
as above. These are served under `/docs`.

## Site, theme, and structure

The site itself — theme, navbar, homepage, and the list of products — is owned by
this repo:

- Products are declared in [`docs.manifest.json`](docs.manifest.json).
- Theme/colors live in `src/css/custom.css`.
- The landing page is `src/pages/index.tsx`.

## Before opening a PR

Run a local build to catch broken links and bad frontmatter:

```bash
npm install
npm run build
```

`onBrokenLinks` is set to `throw`, so a broken cross-reference fails the build
(and the PR build-check) rather than shipping.
